## 1. 문제

무엇이 문제인가를 **관찰된 사실**로 적는다. "이렇게 하면 좋을 것 같다"가 아니라 "지금 X가 일어나고 있고 그 비용이 Y다".

- 실측이 있으면 수치를 적는다.
- 이 문제를 지금 풀어야 하는 이유(트리거)를 한 문장으로.

## 2. 선택지

각 선택지에 **비용과 되돌리는 비용**을 함께 적는다. 기각한 것도 적는다 — 왜 기각했는지가 나중에 같은 논의를 막는다.

**"아무것도 하지 않음"을 항상 넣는다.** 그것이 기준선이다.

## 3. 확정 방향

고른 것과 **고른 이유** 한 단락. [DESIGN_PRINCIPLES.md §F](../DESIGN_PRINCIPLES.md#f-디자인-판단의-기초-원칙-meta)의 원칙 중 무엇이 근거인지 번호로 인용한다.

## 4. 설계

확정 방향의 구체적 형태. 토큰 이름, prop 시그니처, 파일 위치.

## 5. 영향 범위 — 공개 표면 diff

바뀌는 공개 표면을 **전부** 나열한다. 이 저장소의 공개 표면은 다섯 가지다:
1. `src/components/{Name}/index.ts`의 export 이름
2. exported props interface의 prop 이름·타입
3. `{COMPONENT}_{PROP}S` as const 배열의 값
4. `--comp-*` 토큰 **이름**
5. `data-theme` 속성 계약

## 6. 검증 방법

이 결정이 지켜지는지 **무엇이 판정하는가**. 사람이 기억해야 하는 규칙이면 그 사실을 적는다.

- [ ] 자동 검사 — 어느 파일의 어느 검사가 잡는가
